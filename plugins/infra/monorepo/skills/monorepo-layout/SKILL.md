When answering placement questions or generating new files, the layout below is authoritative.

## Top-level layout

```
.
├── CLAUDE.md             # root memory — cross-cutting context
├── Taskfile.yaml         # central task runner (go-task)
├── cog.toml              # cocogito config — version + changelog policy
├── CHANGELOG.md          # generated by cog
├── frontend/             # React app (pnpm + Vite + TypeScript)
│   ├── CLAUDE.md
│   ├── package.json
│   ├── vite.config.ts
│   └── src/
├── website/              # Marketing site (pnpm + Vite + TypeScript)
│   ├── CLAUDE.md
│   ├── package.json
│   ├── vite.config.ts
│   └── src/
└── backends/
    └── <name>/           # Rails API (one or more)
        ├── CLAUDE.md
        ├── Gemfile
        ├── config/
        ├── app/
        └── spec/
```

## Conventions

- **Package manager:** `pnpm` for `frontend/` and `website/`. Never `npm` or `yarn` in those packages.
- **Build tool:** Vite for both JS packages.
- **Backend stack:** Rails API mode. One Rails app per `backends/<name>/`.
- **Task runner:** All multi-step or cross-package commands go through `Taskfile.yaml` at the repo root. Per-package work can use `pnpm`/`bundle` scripts directly, but anything cross-cutting is a Task.
- **Versioning:** Single repo-wide version managed by cocogito at the root. There is no per-package version.
- **Commits:** Conventional commits, enforced by `cog verify`.
- **Changelog:** Generated from commits by `cog changelog`. Do not hand-edit.

## Naming

- Backend directories: kebab-case, descriptive (`auth`, `billing`, `notifications`), placed at `backends/<name>/`.
- Task names in `Taskfile.yaml`: namespaced when package-specific (`frontend:dev`, `auth:test`, `release:bump`).

## When the layout is ambiguous

If a piece of code does not fit cleanly into `frontend/`, `website/`, or `backends/<name>/`, it does not belong in the repo yet — flag it and ask before creating a new top-level directory.

## Companion plugins

This monorepo plugin handles orchestration only. Stack-specific work (React patterns, Rails generators, etc.) belongs to dedicated frontend / backend plugins. Do not embed stack-specific knowledge in this skill.
